บทที่ 6 · BPMN — Business Process Model and Notation

⭐ ออกสอบเขียนข้อ 1 แน่นอน: ให้โจทย์กรณี 3-4 หน้า แล้วเขียน BPMN แบบ Swimlane — บทนี้สอนทุกสัญลักษณ์ + วิธีแปลงโจทย์เป็นแผนภาพ ทีละขั้น พร้อมตัวอย่างเต็ม

  • "ย้ำว่าอย่าเว้นว่าง — แค่เขียนก็มีคะแนนแล้ว" เขียนเท่าที่เข้าใจให้เต็มกระดาษ อย่าทิ้งข้อ!

1. BPMN คืออะไร

  • มาตรฐานของ OMG (ปัจจุบันคือ BPMN 2.0) — รองรับ tool กว่า 70 ตัว ใช้ได้ทั้งโมเดลเชิงแนวคิด (conceptual) และโมเดลที่รันได้จริง (executable)
  • ตำแหน่งใน BPM Lifecycle: Process identification → Process discovery (สร้าง As-is) → Process analysis → Process redesign (สร้าง To-be) → Process implementation → Process monitoring & controlling (วนกลับเป็นวงจรต่อเนื่อง)
  • จุดมุ่งหมายของการทำโมเดลกระบวนการ: Communication (สื่อสาร) · Documentation (บันทึก) · Analysis เช่น simulation · Automation · Testing · ได้ Conformance & performance insights
  • ทำไมต้องมี "ภาษากลาง": ป้องกัน Tower of Babel — ต่างคนต่างวาด ต่างคนต่างเข้าใจ (จาก handout BPAD: จุดรากของโครงการล้มเหลวมากมายคือจุดอ่อนด้าน Business Analysis) · BPMN คือภาษาที่ธุรกิจเข้าใจได้และมีความเข้มงวดพอสำหรับ IT — What (ธุรกิจ define) ส่งต่อให้ IT เป็น How

2. องค์ประกอบหลัก 4 อย่าง (อย่างอื่นต่อยอดจาก 4 นี้)

Events — เหตุการณ์ (สิ่งที่ "เกิดขึ้น" ณ ชั่วขณะ ไม่ใช่สิ่งที่เราทำ)

  • Start event — จุดเริ่ม สร้าง token แล้วปล่อยให้วิ่งในกระบวนการ ("token source") · ตัวอย่าง: Purchase order received
  • End event — จุดจบ ดูด token ทิ้ง ("token sink") · บอกว่า instance จบด้วยผลลัพธ์ใด · ตัวอย่าง: Order fulfilled / Order rejected
  • Intermediate event — เหตุการณ์ระหว่างทาง เช่น รอรับข้อความ/ถึงเวลา (timer)

Activities — งาน

  • Task = หน่วยงานเดี่ยว · Subprocess = ชุดงานที่ม้วนรวมเป็นกล่องเดียว (คลิกขยายดูได้) · Transaction = งานที่ต้องสำเร็จทั้งหมด ไม่งั้นยกเลิก/ย้อน (compensation)
  • Task types (แบบละเอียดของ BPMN): User (คนทำผ่านแอป) · Service (ระบบอัตโนมัติ) · Send / Receive (ส่ง/รอรับข้อความ) · Script (engine รัน) · Manual (มือ ไม่มีระบบ) · Business Rule (ส่งเข้า rule engine)

3. ตั้งชื่ออย่างไร (Naming Conventions — ให้คะแนนตรงนี้แน่นอน!)

📖 กฎการตั้งชื่อ
  1. ทุก event และ task ต้องมีชื่อเสมอ
  2. Task/Activity = Verb + Business Object (กริยา + คำนาม) เช่น Issue Driver Licence, Check stock availability, Assess credit risk
  3. Message Event = Object + Past Participle (V3) เช่น Invoice received, Claim settled, Purchase order received
  4. เลี่ยงกริยากว้าง ๆ เช่น Handle, Record, Manage
  5. ทุกเส้นออกจาก XOR-split ต้องติด condition เช่น "Items in stock" / "Items not in stock"

เพิ่มเติม (guidelines): เงื่อนไขบนเส้นอ้างอิงถึง object ("Policy is invalid") · ผังไล่จากซ้ายบนไปขวาล่าง · เส้นตรง ไม่ตัดกันถ้าเลี่ยงได้

4. Token Game — ทำความเข้าใจ "การรัน" ของโมเดล

จินตนาการว่ามี เหรียญ (token) วิ่งตามเส้น: ออกจาก start → เข้ากิจกรรม (ทำงาน) → เจอ gateway แยกทาง → ไปจนถึง end · Order #1 #2 #3 = 3 instance ที่มี token ของตัวเองวิ่งพร้อมกันได้

5. Gateways 3 แบบ — หัวใจของการสอบ

Gatewayสัญลักษณ์Split (แยก)Join (รวม)ใช้เมื่อ
XOR× ในเพชรเลือก 1 เส้นตามเงื่อนไข (เส้นอื่นไม่ทำ)พอเส้นใดเส้นหนึ่งมาถึงก็เดินต่อจุดตัดสินใจ (มีของ/ไม่มีของ, ผ่าน/ไม่ผ่าน)
AND+ ในเพชรtoken แตกไปทุกเส้น (ไม่ต้องมีเงื่อนไข)รอทุกเส้นมาบรรจบแล้วจึงต่องานควรทำพร้อมกันได้ (ออกใบเสร็จ ∥ จัดส่ง)
OR○ ในเพชร1 หรือหลายเส้น ตามเงื่อนไขแต่ละเส้นรอเฉพาะเส้นที่ activeทำงานบางส่วนตามเงื่อนไข (เลี่ยงถ้าไม่จำเป็น)
⚠️ Default Flow คืออะไร?

เส้นทาง "สำรอง" ของ (X)OR-split ที่จะถูกเลือกโดยอัตโนมัติเมื่อเงื่อนไขอื่น ๆ เป็นเท็จทั้งหมด (ขีดทับที่ปลายเส้น) — เช่น เส้น "อื่น ๆ / ไม่ตรงเงื่อนไขใด"

🧠 หลักจับคู่ (Model in blocks)

จับคู่ split กับ join ชนิดเดียวกันเสมอ: AND-split ↔ AND-join · XOR-split ↔ XOR-join · ข้อยกเว้นที่ยอมได้: XOR-split ที่แยกไป 2 end events คนละผลลัพธ์ (เช่น สำเร็จ/ยกเลิก) ไม่ต้องมี join ปิดท้าย · ผิดพลาดก็คือ deadlock/livelock ตามที่เรียนในบท 5

6. Pool, Lane และ Message Flow (โจทย์เขียนของเขา Swimlane!)

  • Pool = ผู้เข้าร่วมรายใหญ่หนึ่งฝ่าย (บริษัท/องค์กร) — ใช้แทน resource class · Lane = สายย่อยใน pool แทนแผนก/บทบาทภายใน/ระบบ (เช่น ERP, CRM)
  • ประโยชน์ของ swimlane: เห็น ใครทำอะไร เมื่อไร ตอบสนองอะไร · เห็น handoff (การส่งมอบงานระหว่างหน่วยงาน) · เห็นงานซ้ำซ้อน
  • กฎไวยากรณ์ (ออกสอบ!):
    1. Sequence Flow ข้ามขอบ Pool ไม่ได้ (เพราะคนละฝ่ายควบคุม) — แต่ Message Flow ข้ามได้
    2. Sequence Flow และ Message Flow ข้าม Lane ได้ (เพราะ lane อยู่ใน pool เดียวกัน)
    3. Message Flow ต่อภายใน pool เดียวกันห้าม (ต้องเชื่อม 2 pool เท่านั้น)
  • Message flow ชี้ได้ 2 แบบ: โดนขอบ pool (ข้อความเพื่อบอกข่าว) หรือ ชี้ที่ activity/event ใน pool นั้น (ข้อความไปกระตุ้นงานนั้น)

7. Data / Artifacts — ของที่ไหลในกระบวนการ

  • Data Object (ใบกระดาษหลังแผ่นเบา) = สิ่งที่ activity ต้องใช้ (input) หรือผลิตออกมา (output) — เป็นของจริงหรืออิเล็กทรอนิกส์ก็ได้ เช่น Purchase Order [checked], Invoice, Shipment notice
  • Data Store (รูปทรงกระบอก) = ที่เก็บถาวรที่ใช้ข้าม instance เช่น Orders DB, Warehouse DB
  • Text Annotation (วงเล็บเปิด) = หมายเหตุอธิบายเพิ่ม — ไม่มีผลกับการไหลของ token
  • ในระดับละเอียด: Data inputs / outputs / collections / stores (จาก handout BPAD) + Group (กล่องจัดกลุ่มงาน) เพื่อให้อ่านง่าย

8. วงจรย้อนกลับ (Rework Loop) — แบบฝึกจากเอกสาร

📋 โจทย์: ร่างหนังสือตอบรัฐมนตรี (Address ministerial correspondence)

"เมื่อได้รับคำร้องทางรัฐมนตรี → ลงทะเบียนในระบบ → สืบสวนเพื่อเตรียมคำตอบ → เตรียมคำตอบโดยเจ้าหน้าที่ตู้ (cabinet officer) → หัวหน้าทะเบียน (principal registrar) ตรวจคำตอบ → ถ้าไม่อนุมัติ ให้เตรียมใหม่ → เสร็จเมื่ออนุมัติ"

9. 🖊️ แปลงโจทย์เป็น BPMN ทีละขั้น (ทำตามนี้ในห้องสอบ!)

โจทย์ฝึก (Order-to-Cash ฉบับเต็ม): "กระบวนการเริ่มเมื่อได้รับใบสั่งซื้อจากลูกค้า จากนั้นตรวจสอบสต๊อกว่ามีสินค้าหรือไม่ ถ้ามี → ยืนยันออเดอร์ แล้วออกใบแจ้งหนี้กับจัดส่งสินค้า (ทำพร้อมกันตามลำดับใดก็ได้) แล้วจัดเก็บเอกสารเสร็จสิ้น · ถ้าไม่มี → ปฏิเสธออเดอร์ แล้วจบ"

  1. ขั้น 1 — หา Trigger และ Outcomes (ขอบเขต) Trigger = "ได้รับใบสั่งซื้อ" → start event · ผลลัพธ์ = "สำเร็จ (fulfilled)" และ "ถูกปฏิเสธ (rejected)" → end event 2 อัน
  2. ขั้น 2 — ขีดเส้นใต้ "กริยา + กรรม" ตรวจสอบสต๊อก / ยืนยันออเดอร์ / ออกใบแจ้งหนี้ / จัดส่งสินค้า / จัดเก็บเอกสาร / ปฏิเสธออเดอร์ → ทุกตัวคือ activity (ชื่อรูป Verb+Noun อยู่แล้ว)
  3. ขั้น 3 — หาคำบอกทางแยก "ถ้ามี / ถ้าไม่มี" = XOR-split (เลือกเส้นเดียว) พร้อมเขียนเงื่อนไขบนเส้น: "Items in stock" / "Items not in stock"
  4. ขั้น 4 — หาคำบอกขนาน "พร้อมกัน / ตามลำดับใดก็ได้ (in any order)" = AND-split + AND-join ครอบ "ออกใบแจ้งหนี้" กับ "จัดส่งสินค้า"
  5. ขั้น 5 — มองหา "ใครทำ" ใส่ Pool/Lane ตามที่โจทย์บอก (Sales ตรวจสต๊อก/ยืนยัน, Warehouse จัดส่ง, Finance ออกใบเสร็จ) — ส่วนลูกค้าเป็น pool แยกถ้าโจทย์เล่าฝั่งลูกค้าด้วย
  6. ขั้น 6 — ต่อเส้น + ตรวจกฎ ต่อ sequence flow ให้ต่อเนื่อง start → ... → end ทุกเส้นทาง · ตรวจ: ทุกกิจกรรมมีเส้นเข้า-ออก · ทุกเส้น XOR มีเงื่อนไข · split-join จับคู่ชนิดเดียวกัน · ไม่มี node ลอย
🎯 Checklist ก่อนส่งกระดาษ (ข้อเขียนข้อ 1)
  • ☐ มี start event 1 อัน (หรือ 1 ต่อ trigger) และ end event ครบตามผลลัพธ์
  • ☐ ชื่อกิจกรรมเป็น Verb + Object ทุกช่อง / ชื่อ event เป็น คำนาม + V3
  • ☐ ทุกเส้นออกจาก XOR มีเงื่อนไขกำกับ
  • ☐ AND-split จับคู่ AND-join เป็นบล็อก
  • ☐ Sequence flow ไม่ข้าม pool · Message flow เส้นประข้าม pool เท่านั้น
  • ☐ มี Swimlane แบ่งตามผู้ทำ (โจทย์ของเขา Swimlane!)
  • ☐ ไม่มีกิจกรรมลอย ๆ / เส้นหลุด — แล้วเขียนเต็มพื้นที่ อย่าเว้นว่าง!

10. บทเรียนจากคลิปอาจารย์ (สรุปจาก NotebookLM)

🎬 จุดเน้นที่อาจารย์ย้ำในคลิป
  • BPM-PAD: BPMN = ภาษากลาง Business–IT · mapping Exclusive=XOR / Inclusive=OR / Parallel=AND · แปลง diagram → BPEL (ภาษาสั่งรัน Web Services) ได้
  • BPM-PM: สอน Order-to-Cash + กรณีร่าง/อนุมัติแถลงการณ์ (PR) ที่มี rework loop · เดิน token ให้ดู 2 scenario เทียบ Parallel vs Exclusive · Decision Point = กิจกรรมสุดท้ายก่อนแยกเส้น · swimlanes เห็น handover (Sales, Warehouse) · lifecycle ต้องมี Monitoring & Control ป้อนกลับ
  • BPM-PD: George vs Sarah (domain expert vs process analyst) · หา boundaries + positive/negative outcomes · 1 start ต่อ trigger, 1 end ต่อ outcome · เลี่ยง OR · ไม่เกิน 30 nodes

สรุปท้ายบท

✅ ต้องจำให้ได้จากบทนี้
  1. 4 core elements: Activity · Event · Gateway · Sequence flow
  2. ชื่อ: Task = Verb+Noun · Event = Noun+V3 · เส้น XOR ติด condition · ห้ามใช้ Handle/Record
  3. XOR เลือกเดียว (มี default flow) · AND ทำครบทุกเส้น · OR อย่างน้อยหนึ่ง (เลี่ยงถ้าได้)
  4. Pool = ฝ่ายรายใหญ่ · Lane = แผนก/บทบาทใน pool · Sequence flow ห้ามข้าม pool · Message flow (เส้นประ) ห้ามใน pool เดียวกัน
  5. Data object (input/output) · Data store (ถาวร) · Annotation (ไม่กระทบ token)
  6. Rework loop = XOR-join เข้า + XOR-split ออก
  7. เทคนิคทำโจทย์: trigger→outcomes→กริยา+กรรม→คำบอกแยก/ขนาน→ใครทำ→ต่อเส้นตรวจกฎ
