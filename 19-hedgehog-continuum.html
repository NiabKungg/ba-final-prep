บทที่ 19 · The Hedgehog Concept & Requirement Continuum

ปิดท้ายด้วยปรัชญาของคนทำ requirements: เจตจำนงแบบเฮดจ์ฮอก (อย่าเป็นจิ้งจอก!) และวงจร Requirements ที่หมุนวนต่อเนื่อง (ควิซ 11 ข้อ 2-4)

1. The Hedgehog and the Fox — คุณเป็นสัตว์แบบไหน?

📖 ที่มา (Isaiah Berlin, จากนิทานกรีกโบราณ)

"The fox knows many things, but the hedgehog knows one big thing." — จิ้งจอกรู้เรื่องมากมายแต่กระจัดกระจาย · เฮดจ์ฮอกรู้ "หลักการใหญ่หนึ่งเดียว" ที่ใช้ทุกอย่าง

Jim Collins: "ผู้นำที่พาจากดีสู่ยอดเยี่ยม (good-to-great) ล้วนเป็น hedgehog — พวกเขารู้วิธีทำให้โลกที่ซับซ้อนง่ายลงเป็นแนวคิดจัดระเบียบหนึ่งเดียว — หลักการพื้นฐานที่รวมศูนย์ จัดระเบียบ และชี้นำการตัดสินใจทั้งหมด"

💭 ในบริบท BA

❌ จิ้งจอก-style: BA ที่ไล่เรียนเรื่องเทคนิคกระจัดกระจาย รู้มั่วไปหมดแต่ไม่มีหลักยึด · ✅ Hedgehog-style: มี "เข็มทิศเดียว" คือ Business Need — ทุกคำถาม ทุกการตัดสินใจ อ้างกลับไปที่ความต้องการทางธุรกิจเสมอ

BA Hedgehog — วงกลมความสำเร็จ 3 ด้าน

Syllogism — ห่วงโซ่เหตุผลของ Hedgehog (ท่อง!)

🎯 จำลำดับนี้ (ควิซถามตรง ๆ)

ต้องการการตัดสินใจที่ดี → ต้องถามคำถามที่ดี/ตรงประเด็น → คำถามจะตรงประเด็น ก็ต่อเมื่อรู้วัตถุประสงค์ว่าถามไปทำไม → เหตุที่มีวัตถุประสงค์ คือมีBusiness Need ที่ต้องบรรลุ → "ดังนั้น Business Need คืออะไร?"

2. Requirement Continuum — วงจร requirements ที่หมุนไม่หยุด

Key Points ของ Continuum (จากเอกสาร — ออกสอบ)

  1. เป็น life cycle การพัฒนา requirements ที่ใช้ได้ทั้ง Agile และ Waterfall
  2. เริ่มจาก Functional Decomposition ของระบบ/capability ลงมาถึงระดับ Feature
  3. Features ถูกขยายเป็น User Stories ที่มี Acceptance Criteria = guardrails บอกว่าอะไรคือ "สมบูรณ์และสำเร็จ"
  4. QA validate + test บน prototype environment ก่อน/ควบคู่การพัฒนา → แล้ว delivery team จึง develop · timeframe จบ sprint
  5. แต่ละ sprint นิยามด้วย user stories → จบ sprint สร้าง feature ใหม่ → วงจรต่อเนื่องจนโครงการเสร็จ (❌ ไม่ใช่เส้นตรงทางเดียวที่ห้ามย้อน!)

3. Functional Decomposition — โครงสร้างลำดับชั้น

🎯 ควิซตรง ๆ เรื่อง Decomposition
  • ✅ เริ่มจาก Capability (สูงสุด) → แตกลงมาเป็น Feature level
  • ✅ Feature → User Stories + Acceptance Criteria
  • ❌ ระดับล่างสุดใส่ data values/Data type ทันที (ผิด — "detail, but not data")
  • ❌ ใช้ได้แค่ Waterfall (ผิด — ใช้ได้ทั้ง Agile) · ❌ ละเว้น traceability (ผิด — ต้องมี)

สรุปท้ายบท

✅ ต้องจำให้ได้
  1. Hedgehog = ทำโลกซับซ้อนให้ง่ายเป็นหลักการเดียวที่ชี้นำทุกการตัดสินใจ (BA: ยึด Business Need) · ❌ จิ้งจอกรู้กระจัดกระจาย
  2. BA Hedgehog = สมดุล ความรู้+ลงมือของ BA · พัฒนา/ทดสอบ/ใช้ requirements · วินัยกระบวนการ → Good Product
  3. คำถามดีมาจากวัตถุประสงค์ มาจาก Business Need
  4. Continuum: FD(Capability→Feature) → User Stories(+AC เป็น guardrails) → Delivery+QA (prototype) → วนซ้ำ — Agile+Waterfall ใช้ได้
  5. Decomposition ล่างสุด = Function (ไม่ใส่ data type)
